This is the sixth release candidate of 3.6.0. The console has a new structure: Your account, Rules and Server sections in the sidebar, one Add computers page and a search that finds settings. An account can be signed in on several browsers at once. The chat is rebuilt as a support inbox and a team chat. A new computer is walked through its first steps as it joins, and the invite comes as a welcome mail. The device page draws usage graphs again, and remote sessions open inside the console. It goes with the NeoDesk client [1.5.0-rc.8](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.8); with 1.5.0-rc.7 some parts are missing, see [Clients](#clients).

## Updating from 3.6.0-rc.5

Update as usual: `sudo neodesk-setup --update` on Linux, `sudo bash /opt/neodesk/docker/neodesk-docker.sh update` with Docker, `& 'C:\NeoDesk\neodesk.ps1' -Update` on Windows, or **Server › Updates** in the console. Then check these points.

### Several sessions per account is the new default

An account now stays signed in on up to 10 browsers at once. Before, a new sign-in ended the account's other session. To keep that rule, turn on **One session per account** under **Settings › Sign-in**.

- The env file of every Linux and Windows install set `SESSION_MAX_PER_USER=1`. At its first start this release empties that line, if it is still as the installer wrote it, and the server log says "Changed defaults of this release". A value or comment you changed stays.
- When `SESSION_MAX_PER_USER` has a value, it decides, and **One session per account** shows that it is locked. `0` means no limit.
- Docker installs pass the value from /opt/neodesk/docker/.env, which is empty unless you set it.

### A computer that joins again needs the client 1.5.0-rc.8

A computer the server already knows can join again with an invite only when its NeoDesk proves the computer's key. The client 1.5.0-rc.7 can't, so such a join is refused with "This computer's ID is already enrolled on this server. Update NeoDesk on this computer and open the invite again, or ask your administrator to delete the device in the console." The invite stays unused. New computers join as before, with any client version, and computers that joined before keep working.

Update such a computer to the client [1.5.0-rc.8](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.8), or delete the device in the console before it joins again with an invite.

### The chat moves its old messages once

At the first start the server moves the earlier chat's messages, in one go:

- direct messages into the conversation of their two people, which only they read;
- groups with two or more accounts into groups of those accounts, without the computers;
- what a computer wrote into that computer's conversation;
- everything else, such as messages to an account that is gone, under **Old messages** in **Team**, which only admins read.

The permission **Chat access** is split into **Support chat** and **Team chat**. What you had set for a role under **Chat access** now holds for both, and an API token with **Chat access** gets both. **Assign conversations** and **Manage canned replies** are new. **Chat with computers** is on.

### Console addresses moved

The console has new places for many pages. The old addresses lead to the new ones, also from bookmarks and links in mails:

| Old address | New address |
|---|---|
| /settings?tab=backup | /server/backups |
| /settings?tab=updates | /server/updates |
| /settings?tab=advanced | /server/config-files |
| /security-audit?tab=overview | /security-checks?tab=checks |
| /security-audit?tab=hardening | /security-checks?tab=hardening |
| /security-audit?tab=sessions | /account#sessions |
| /commercialization | /billing |
| /client-branding | /settings?tab=brand#client-app |
| /api-tokens | /account#api-tokens |
| /keys | /devices/add?tab=manual |
| /tokens | /devices/add?tab=tokens |
| /pairing | /devices/add?tab=pairing |
| /agents, /generator | /devices/add?tab=agents |

Your own password and two-factor sign-in left **Settings › Sign-in** for Your account. **Enrollment requests** are now **Join requests**, under the same address.

### Docker installs and the firewall

The one-line Docker install now opens the console's ports in ufw or firewalld by the same rule as the Linux and Windows installers: 3375 only when no reverse proxy is set (`TRUST_PROXY`), 5443 only with HTTPS on. When it leaves the console closed, it prints the command to open it by hand.

It doesn't close what an earlier install opened. That one opened 3375 and 5443 on every install without `--domain`. If nothing serves HTTPS on 5443, or a reverse proxy sits in front of the console, close them yourself, for example:

```bash
sudo ufw delete allow 5443/tcp
sudo firewall-cmd --permanent --remove-port=5443/tcp && sudo firewall-cmd --reload
```

## What's new

### Several sessions per account

**Signed-in devices** in the account menu and on Your account lists where your account is signed in: browser and system, address, when it signed in and when it was last used. Each entry has **Sign out**, and **Sign out everywhere else** ends all but this browser. The browser that was signed out is told why, by whichever of its requests or open pages notices first. Admins with **Edit users** find the same list for a person under **Signed-in devices…** in the row menu on **Users**.

The command line has `neodesk sessions list`, `sessions list-for`, `sessions end` and `sessions end-all`, and `neodesk settings console-sessions-set` sets **One session per account**. An API token can't end its own account's sessions.

### Adding computers

- **Welcome mail.** An invite sent by email names who invited the person and your server, and has your logo (an uploaded PNG, JPEG or GIF on an HTTPS console, otherwise the server's name), your accent colour, one button, **Set up NeoDesk**, and three steps. The invite page shows the same steps on Windows and Mac, and the download for the person's system, also without JavaScript.
- **Guided first join.** After **Create invite**, the sheet waits for the computer. When it joins, the sheet walks through **Name**, **Folder**, **How you reach it** and **Test session**. **Skip** keeps the computer as it joined. A computer that comes back with another key gets **Approve new key** in the sheet, which asks first.
- **Which computers joined.** The console shows which computers joined with an invite, also once the invite is used up. `neodesk invites show <id>` prints the same.

### A new console structure

- **Your account** has your profile, password, two-factor sign-in, signed-in devices, API tokens and your preferences. It opens from the account menu at the end of the top bar.
- **The sidebar** has seven sections: Devices, Support, People, Activity, Rules, Server and Settings. Rules holds policies, alerts and automation, USB and drive access, data loss prevention and device identity. Server holds server status, relay servers, backups, updates, configuration files and the capacity test.
- **Settings** keeps only settings. Directory (LDAP), Single sign-on, Joining and MeshCentral are tabs of their own, and Branding next to Appearance has the name, logo, sign-in page, download page, remote viewer and client app. Rarely set options sit behind **Advanced**.
- **Activity** splits **Security checks** from the **Audit log**, and **Billing** is one page with Packages, Sessions and Reports.
- **Devices › Add computers** gathers invites, device tokens, pairing codes, support agents and manual setup. Every account sees the page; each tab needs the permission its old page needed.
- **The top bar** has the breadcrumb, the search, Quick support, the chat, notifications, Help as an icon and the account menu. Theme, language and accessibility moved into the account menu. Refresh is gone: the audit log, network monitoring, users, organizations, device tokens and billing sessions load again every 30 seconds while they are on screen.
- **The search** (Ctrl+K) finds every setting and opens its tab at the setting, and finds actions such as Quick support, Add a computer, New device token, Add user, New API token and Sign out, each for accounts that see its button. English and German words find the same setting.
- **On a phone** every dialog is a full-height sheet with its buttons at the bottom, and fields fill their row.
- **Help** links the documentation, the NeoDesk Discord and the GitHub repository, and leads to Platform support. A right-click on NeoDesk's own logo opens the brand guide.

### Chat

- **Support** is a shared inbox with one conversation per computer: **Open**, **Mine** and **Closed**, **Take over**, **Hand to** a colleague, close with a note that can resolve the computer's help request, and **New ticket** with the computer filled in.
- **Team** lists colleagues with their role and status. A direct conversation reaches only its two people, and groups have names and members.
- **Everywhere in the console**: the chat button in the top bar opens a panel over any page. Unread counts show on the button, in the sidebar and in the tab's title, with browser notifications and, if you want, a sound.
- **Messages** can be replies, edited for 24 hours, deleted with a trail in the audit log, and carry reactions, pasted pictures, dropped files and canned replies.
- **Search** finds messages by their text in the conversations you can read and opens the conversation at the message.
- **Mail when a person waits**: after 15 minutes without an answer, the console mails whoever has the conversation, or else the colleagues who may assign it. The mail is in your server's branding and in each recipient's language.
- **Chat with computers** under **Chat settings for this server** in the chat's menu turns the computers' side off. Team chat keeps working, and the Support list says it is off.

Computers reach the chat and send and fetch its files on the port they already use for the server's API (21121 by default), or at the console's address, so no new port has to be opened. The chat for the NeoDesk app on the computer needs the client 1.5.0-rc.8 or later, see [Clients](#clients). [Chat](https://docs.neode.sk/console/chat/) has the details.

### Live usage data

The device page shows real values again. Every heartbeat of a NeoDesk client now adds a sample to the usage history, which **Metrics** draws as graphs, with a network graph next to them, and Current load has a Network row. CPU load and network rates need the next client, see [Clients](#clients). When a device has no data, the page says why: none yet, a client that sends none (stock RustDesk), or usage turned off there. **Live data** asks an online NeoDesk client for a new copy instead of calling it offline.

The client API now counts heartbeats per device, 40 a minute, so offices with many computers behind one address no longer lose heartbeats and usage data. A flood brake of 6000 a minute per address stays. A refused call gets 429 with Retry-After and a line in the log, and /metrics counts them.

### Remote sessions inside the console

- **Sessions open inside the console**, as tabs that stay connected while you work on other pages. A strip under the top bar lists them, the sidebar folds away, and **Open in new tab** and full screen stay. **Remote sessions** in the sidebar lists the open sessions and connects by ID or from the address book. Guests keep the viewer in a tab of its own. Signing out ends the sessions and says how many are open.
- **Copy and paste** of text and images work both ways with Ctrl+C and Ctrl+V, without a button: up to 4 MB of text and 8 MB of images to the computer, up to 40 MB from it. Clipboard and file blocks the computer compresses now arrive too.
- **Firefox**: the viewer says which shortcuts Firefox keeps in full screen and that it can't place display windows. **Actions** sends the Windows key and Alt+Tab.
- **On a Mac**, Cmd with C, V, X, A, Z, S or F goes to a computer that isn't a Mac as Ctrl, with a switch to turn it off.
- **Phones** held sideways open sessions from 640 pixels wide.
- A touchpad scrolls one notch per swipe step, in Chromium and Firefox alike.
- A computer where the person accepts sessions by clicking shows its prompt at once, without a password typed first.
- The viewer and the saved sign-in sheet say that saved sign-in works on Windows only, on a computer that isn't.
- **Connect** in a device's side panel closes the panel when the session opens inside the console.

A copy made in Notepad on a Windows computer has been seen to reach the viewer one copy late. Twice in the lab, the breadcrumb and the title of a session page said "Remote sessions" instead of the device's name.

### Security fixes

- A person with an invite who knew a computer's ID could join under that ID. That ended the real computer's device token and moved it into the invite's folder. A join under a known ID now needs the proof of that computer's key, and a refused join shows in the **Audit log** as "Join refused: no proof of the computer's key", once a minute per computer.
- Direct chat messages between colleagues reached every chat user, and the first reader marked a message read for everyone. A direct message now reaches only its two people, and every account has its own read marks.
- The one-line Docker install opened 5443 although nothing served HTTPS there, and 3375 with a reverse proxy in front. See [Docker installs and the firewall](#docker-installs-and-the-firewall).
- The live updates, chat and remote sessions of a browser now close as soon as its session ends. Before, only the device status noticed, within 10 seconds.
- Turning your own two-factor sign-in on or off ends your other sessions, and resetting a password on the server's command line signs that account out of the console everywhere.

### Smaller changes

- A computer's message without a conversation shows in that computer's conversation. In 3.6.0-rc.5 it went into a conversation nobody saw.
- A computer's open help request links to its conversation as soon as the computer writes.
- Saved sign-in's one use per remote session belongs to the browser whose viewer opened the session.
- The command line has 564 commands in 60 groups. New are the `sessions` group, 21 `chat` commands for the inbox, conversations, canned replies and the chat's settings, `invites show`, and `settings console-sessions` and `console-sessions-set`.
- The console's German and the German mails the server sends now say "du".
- The LICENSE notice says RustDesk is made by Purslane Tech Pte. Ltd. and that NeoDesk is not affiliated with or endorsed by RustDesk or Purslane Tech.

## Known issues

- Saved sign-in with the client 1.5.0-rc.7, where the browser types the details, and Connect with the address book's device password have only run in the test suites, not against a real Windows computer. The sealed way of the next client has run in the lab.
- A computer with a client older than 1.5.0-rc.8 has no chat outside a remote session. It shows "Not reachable now" in Support, and the server keeps your messages.
- In a support conversation, your message shows **Seen** as soon as a colleague opens the conversation, also when nobody at the computer has read it.
- The overview's client setup part still speaks of RustDesk: it shows the values for RustDesk's network settings and offers **Download RustDesk**, and doesn't point to the NeoDesk app or to invites under **Devices › Add computers**.
- The Docker manager's update checks the compose file and its own new copy against the release's SHA256SUMS, but doesn't check that list's signature (SHA256SUMS.sig), as neodesk.sh does.
- A computer whose NeoDesk is paused (**Stop accepting connections** in the tray of the client 1.5.0-rc.7) shows offline, and the viewer says to turn it on.
- A client that joined a Docker server before its console moved to port 3375 keeps the old address, so a bare join or support code goes to port 5000, where nothing answers. Send the whole link instead.
- The console offers the NeoDesk agent's terminal and files only to super admins, also when another role holds those permissions.
- Revoking an API token leaves the accounts it made. Enrollment tokens of agent templates can't be revoked at all.
- `neodesk mcp` with an MCP client that can't ask you (no elicitation) still makes the agent confirm first and leaves asking you to the agent, so give an agent a token with only the permissions it needs.
- `neodesk billing clock-set` resets every setting you leave out, and `neodesk billing mail-settings-set` turns on every switch you leave out.
- On SQLite, a backup archive holds the database file twice.
- HTTPS with Let's Encrypt hasn't been run against Let's Encrypt itself yet, not even its staging server. Whether Traefik replaces a staging certificate when you switch to a real one isn't known, and `--no-traefik` also removes a `TRUST_PROXY` you had set for a proxy of your own.
- Clients that use the console's address as their API server are signed out after the session duration even while they are in use: **Extend session on activity** and **Maximum session lifetime** don't apply to them.
- Some permissions only work together with another one, and the Permissions page doesn't say so. Delete devices, Ban, Change device ID and Change connection mode need Edit devices, and Create and Delete users need Edit users, for example.
- Relay servers: the assignment rules are saved but not used; every device uses the default relay.
- USB and drive access and Fleet tasks can't save yet, as the banners on both pages say.
- A slow single sign-on provider ends in "OIDC authentication failed" or a bare page that says "OIDC callback proxy failed".

## Clients

Everything in this release works with the NeoDesk client [1.5.0-rc.7](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.7), apart from these parts, which need the client [1.5.0-rc.8](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.8) or later:

- **Joining again** with an invite under an ID the server knows.
- **CPU load and network rates** on the device page. With 1.5.0-rc.7 the page shows memory and disk and says "This client version doesn't measure CPU load. Update the NeoDesk client to see it." The CPU value of 1.5.0-rc.7 was wrong (100 % on Windows, 0 % on Linux), so the server doesn't keep it.
- **The chat on the computer**, outside a remote session. That client reaches the chat on the server's API port, where it already connects.
- **Saved sign-in without the password in the browser**, as the notes of 3.6.0-rc.5 describe.

Stock RustDesk clients connect as before. They send no usage data and have no chat outside a session.

## Install

With Docker, the first line installs the newest release, now this one. The second also serves the console over HTTPS at your domain, which has to point at the server, with ports 80 and 443 open:

```bash
curl -fsSL https://neode.sk/install.sh | sudo bash
curl -fsSL https://neode.sk/install.sh | sudo bash -s -- --domain <domain> --letsencrypt-email <email-address>
```

Without Docker, on Linux:

```bash
curl -fsSL https://neode.sk/neodesk.sh | sudo bash
```

The image is `ghcr.io/neodeskapp/neodesk:3.6.0-rc.6`. The [Linux](https://docs.neode.sk/getting-started/linux/) and [Windows](https://docs.neode.sk/getting-started/windows/) pages have the details. A new install's console answers on port 3375, and on 5443 with HTTPS.

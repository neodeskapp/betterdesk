This is the second release candidate of 3.6.0, and the first one as NeoDesk. NeoDesk is a self-hosted remote desktop server for RustDesk clients, with the web console in the same Go binary. It started as a fork of BetterDesk by UNITRONIX and is now developed on its own.

## What's new

### The project is NeoDesk now

The repository is [neodeskapp/neodesk](https://github.com/neodeskapp/neodesk), the client is [neodeskapp/neodesk-client](https://github.com/neodeskapp/neodesk-client), and the documentation is on [neode.sk](https://neode.sk/docs/). The console, the installers, the services, the Docker image and the device API all carry the new name.

### Add a computer

New in 3.6.0. An invite link or code from the console sets up a computer with nothing typed: a Windows setup program named for the invite, a Linux command, or a link that opens NeoDesk on macOS. The computer shows up under Devices, already approved, in the folder you picked. See [Add a computer](https://neode.sk/docs/console/add-a-computer/).

### Quick support

New in 3.6.0. A link for one session that works once, for one hour. The person downloads a small support app and clicks Allow, and you connect without an ID or a password. See [Quick support](https://neode.sk/docs/console/quick-support/).

### Fixes since rc.1

- A socket upgrade with a session cookie and no Origin header got past the console's origin check, which still looked for the old cookie name.
- Support clients are built from the client repository's main branch and checked against its signing key.

## Upgrade notes

This is the first NeoDesk release. There is no migration from 3.6.0-rc.1 or older: the installers don't take over their services, folders, volumes or settings. Install NeoDesk fresh with the steps for [Linux](https://neode.sk/docs/getting-started/linux/), [Docker](https://neode.sk/docs/getting-started/docker/) or [Windows](https://neode.sk/docs/getting-started/windows/).

- Agents and clients from before the rename can't register with or connect to a NeoDesk server, and an older install can't update itself to NeoDesk.
- Everyone signs in to the console again. Theme and sidebar choices start over, and new two-factor set-ups show NeoDesk as the issuer.
- The names that changed:
  - Installers: `neodesk.sh`, `neodesk.ps1` and `neodesk-docker.sh`.
  - Linux: the service `neodesk-server`, the system user `neodesk`, the folder `/opt/neodesk` and the binary `/usr/local/bin/neodesk-server`.
  - Windows: the service `NeoDeskServer` and the folders `C:\NeoDesk` and `C:\NeoDeskConsole`.
  - Docker: the image `ghcr.io/neodeskapp/neodesk`, the container `neodesk`, the volumes `neodesk-data`, `neodesk-console-data` and `neodesk-postgres-data`, and `neodesk-show-admin-credentials`.
  - Environment variables start with `NEODESK_` and `ND_`.
  - Device API: `/api/nd/*`, the sockets `/ws/nd-signal`, `/ws/nd-relay` and `/ws/nd-mgmt`, and the `X-ND-*` headers. The old names are gone, so scripts and integrations that call the API need the new ones.
  - LAN discovery answers `neodesk-discover` probes, and mDNS announces `_neodesk._tcp`.

## Install

On Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/neodeskapp/neodesk/main/neodesk.sh | sudo bash
```

While there is no stable release, the script installs the newest pre-release, this one. The Docker image is `ghcr.io/neodeskapp/neodesk:3.6.0-rc.2`; the [Docker](https://neode.sk/docs/getting-started/docker/) and [Windows](https://neode.sk/docs/getting-started/windows/) pages have their commands.

This is the fourth release candidate of 3.6.0. It adds the `neodesk` command line with API tokens for scripts and AI agents, and a setup guide for the first admin of a new install. A computer whose key changed no longer passes as online while every session to it fails. It goes with the NeoDesk client [1.5.0-rc.6](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.6).

## What's new

### Command line and API tokens

Admins make API tokens for scripts under **API tokens** in the account menu. A token acts as the account that made it, with only the permissions picked for it, read only or read and write, for at most a year and, if you want, only from some addresses. It never gets the server's secrets or more than its account may do, and a revoked token stops working at once.

The `neodesk` command line uses such a token for everything the console's API does: 532 commands in 59 groups, all made from one table. `neodesk describe` prints every command with its arguments and permission as JSON or Markdown. `neodesk mcp` serves the commands as MCP tools for an AI agent, read only unless you add `--allow-writes`. Commands that run something on a device or the server need `--allow-exec` as well, and answers that hold secrets need `--allow-secrets`.

In the Docker image the command is `neodesk`. On Linux hosts `/usr/local/sbin/neodesk` is the installer's manager, so there the command line is `neodesk-server cli`.

```bash
neodesk login --url https://<console-address>
neodesk devices list
neodesk describe --format markdown
```

Put your console's address in place of `<console-address>`. `neodesk login` asks for the token and saves it with the address for the next commands.

### Setup guide for a new install

A new install opens with a setup guide on the overview, for the first admin. Its eight steps are: change the first password, turn on two-factor sign-in, set the address clients use, put HTTPS in front of the console, add your first computer, open a remote session, add the people who help, and make a backup. Each step leads to its place in the console and back, and the server ticks a step by itself once it sees it done. You can hide the guide, and Help and Settings bring it back. The backup step shows only to super admins, who may make a full backup. On the command line, `neodesk setup-guide status` lists the steps.

### A computer keeps its connection after a restart

A Windows computer that joined with an invite could lose its key at the next restart. The server kept the old key and showed the computer online, but every session to it ended with "could not be secured". The server now asks a computer it knows for its key each time it registers. A changed key is refused: the computer shows offline, and with the client 1.5.0-rc.6 its Home and tray say that the server refuses its key. **Approve new key** shows on its device page once its invite runs on the computer again, and the same invite works after the key is approved.

The client half, which keeps the key over a restart, is in the client 1.5.0-rc.6.

### Smaller changes

- Leaving the settings while a save runs waits for the save instead of asking whether to discard what it saves.
- Leaving a page while part of it still loads no longer raises a page error, and a part that failed to load, such as the device panel, loads again the next time you open it.
- Help no longer lists sponsors and supporters, and CHANGELOG.md starts at 3.6.0-rc.2, the first release as NeoDesk.
- Tests that failed now and then, for chat sockets, the relay, mDNS and billing, are stable.

## Upgrade notes

Update by running the installer again, as [Updating](https://neode.sk/docs/operations/updating/) describes. There is still no migration from 3.6.0-rc.1 or older: install NeoDesk fresh.

- Console sessions carry over: nobody has to sign in again.
- **A computer whose key changed since it joined shows offline after the update**, where before it showed online and failed every session. To let it back in, run its invite on it again: its device page then offers **Approve new key**. Approve the key and run the same invite once more. Computers that joined with a client build from CI before 1.5.0-rc.6 lose their key at a restart, so expect this for them.
- The setup guide opens by itself only on a new install. On an install that is in use, Help and Settings show it.
- Quick support choices and the client half of the key fix need the client 1.5.0-rc.6. The client 1.5.0-rc.5 was never published.
- `GET /api/console/supporters` is gone, with the supporters list in Help. Settings, Appearance no longer offers the theme preset of a former sponsor; a console that applied it keeps its look until you apply another one.
- The core script for MeshCentral agents is served at `/neocore.js`. `/meshcore.js` still answers.
- Custom CSS in Settings, Appearance that styles the accessibility helpers or the attestation badge by class name needs the new class names, which start with `nd-`.

## Install

With Docker, the first line installs this release. The second also serves the console over HTTPS at your domain, which has to point at the server, with ports 80 and 443 open:

```bash
curl -fsSL https://raw.githubusercontent.com/neodeskapp/neodesk/main/install.sh | sudo bash -s -- --version 3.6.0-rc.4
curl -fsSL https://raw.githubusercontent.com/neodeskapp/neodesk/main/install.sh | sudo bash -s -- --version 3.6.0-rc.4 --domain <domain> --letsencrypt-email <email-address>
```

The image is `ghcr.io/neodeskapp/neodesk:3.6.0-rc.4`. The [Linux](https://neode.sk/docs/getting-started/linux/) and [Windows](https://neode.sk/docs/getting-started/windows/) pages have the commands without Docker.

## Known issues

- Guest links, device tokens and support passwords that an API token made stay valid after the token is revoked.
- `neodesk mcp` doesn't ask you itself before a tool deletes or ends something. It makes the agent confirm first and leaves asking you to the agent and its MCP client, so give an agent a token with only the permissions it needs.
- A few commands of the command line answer 404, because the console doesn't serve their route.
- Some command line tables show times without a time zone.
- Settings, Backup still shows a Server admin the buttons for full backups, which then refuse with 403.
- On SQLite, a backup archive holds the database file twice.
- The console's links that open a device in an app use `rustdesk://`. They start stock RustDesk, and on a computer with only the NeoDesk client they open it on Windows and nothing on Linux and macOS.
- HTTPS with Let's Encrypt hasn't been run against Let's Encrypt itself yet, not even its staging server. Whether Traefik replaces a staging certificate when you switch to a real one isn't known, and `--no-traefik` also removes a `TRUST_PROXY` you had set for a proxy of your own.
- Clients that use the console's address as their API server are signed out after the session duration even while they are in use: **Extend session on activity** and **Maximum session lifetime** don't apply to them.
- Some permissions only work together with another one, and the Permissions page doesn't say so. Delete devices, Ban, Change device ID and Change connection mode need Edit devices, and Create and Delete users need Edit users, for example.
- Access rules don't reach devices in device groups that are made from tags.
- Relay servers: the assignment rules are saved but not used; every device uses the default relay.
- USB and drive access and Fleet tasks can't save yet, as the banners on both pages say.
- Each browser session start logs a failed request for the quick support password (409), although the session works.
- A slow single sign-on provider ends in "OIDC authentication failed" or a bare page that says "OIDC callback proxy failed".

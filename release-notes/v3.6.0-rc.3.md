This is the third release candidate of 3.6.0. It closes the permission holes that the review of rc.2 found, serves the console over HTTPS on Docker with a certificate from Let's Encrypt, and makes the settings that did nothing on Docker save. It goes with the NeoDesk client [1.5.0-rc.5](https://github.com/neodeskapp/neodesk-client/releases/tag/desktop-v1.5.0-rc.5).

## What's new

### HTTPS on Docker

`--domain` and `--email` put a small Traefik container in front of the console. It gets a certificate from Let's Encrypt and renews it by itself, and the console's own port then answers on the host only. `--letsencrypt-staging` uses Let's Encrypt's staging server for a test run, and `--no-traefik` takes it out again. See [HTTPS with Let's Encrypt](https://neode.sk/docs/getting-started/docker/#https-with-lets-encrypt).

### Security

No account can give itself more than it has any more:

- An API key, the console's own included, no longer creates, changes or deletes accounts, roles, API keys or second factors.
- No account gives a role or a key more permissions than it holds itself, and no account widens its own device or panel access.
- Deleting a user group keeps its panel limits on its members.
- The NeoDesk agent's terminal and files have their own permissions, **Terminal on NeoDesk agents** and **Files on NeoDesk agents**, instead of coming with Edit devices. The client feature switches cover the agent's tools as well.
- Only super admins download, restore or schedule full backups, and the files with password hashes in a backup archive are readable by their owner only.
- Client API tokens keep the saved session duration after a restart.
- Settings, Advanced refuses a session secret the console can't start with, keeps release keys, the client build command and secrets out of the files it writes, and shows the audit log read-only. A broken session secret no longer stops the server.
- The blocklist that Settings, Advanced saves is loaded at the server's start. On Docker it was never loaded before.
- CORS answers only the desktop client's webview and never with cookies, and a Bearer header no longer switches the CSRF check off for a request that the console's cookies authenticate.
- Access rules for users, user groups and device groups apply to their devices, and devices get only their own data loss prevention policies.

### Reinstalled computers

A computer that was reinstalled or reset keeps its ID but comes back with a new key. The server still refuses it, but now keeps the new key as a request: the device list shows the computer offline, and its device page offers **Approve new key**. Once approved, the computer rejoins with the same invite. This needs the client 1.5.0-rc.5.

### Quick support gives only what the person allowed

A quick support session gets the screen, the mouse and the keyboard. Copying text and sending files are choices in the support app, off until the person ticks them, and the server holds the session to them.

### Settings that now save on Docker

- Connection strategy and the time settings save. The server keeps them in its database and applies them at once, and the page shows what the server runs instead of defaults.
- Pairing codes redeem instead of answering 401.
- RDP and VNC targets reconnect after the container restarts.
- Settings, Updates shows commands that fetch the new version.

### The browser viewer over plain HTTP

Over plain HTTP the browser viewer showed a black screen. It now ends the session with a message that it needs HTTPS.

### Directory sign-in

The console waits up to 30 seconds for a slow directory and says when it took too long. A directory account signs in to the account the directory names instead of making a second one under the typed name. LDAP groups are searched as the service account, the role map can name a group by its Group name attribute, and the connection timeout covers LDAPS and StartTLS. LDAP and single sign-on settings that can't work are refused with the reason at the field.

### Restore one part

A restore brings back only the parts you choose: Server device database leaves the console accounts alone, and Console data leaves the devices. It says when a part brought back nothing.

### Smaller fixes

- Phones and keyboards: the top bar, long buttons, status lines and device names stay on the screen, search has Cancel on touch screens, and the remote screen says that F8 leaves it.
- Languages: audit actions and details, hardening checks and the refusals of passwords, two-factor codes, Email and Appearance are in the console's language.
- Appearance: the console background, the web remote client background and the text font reach the pages, a saved look shows at the next page load, and Google fonts are downloaded to the server.
- Installers: a switched-off ufw or firewalld stays as it is, and an invite's Linux install script moves a computer from client 1.5.0-rc.4 to a later build.

## Upgrade notes

Update by running the installer again, as [Updating](https://neode.sk/docs/operations/updating/) describes. There is still no migration from 3.6.0-rc.1 or older: install NeoDesk fresh.

- Console sessions carry over: nobody has to sign in again.
- Permissions that changed:
  - **Remote operator** no longer opens the terminal and the files of NeoDesk agents. Give a role **Terminal on NeoDesk agents** or **Files on NeoDesk agents** where it needs them; Global admin and the super admins have them.
  - **Server admin** no longer sees the whole console API key and can't download, restore or schedule full backups.
  - The IoT gateway and its devices need **View CDAP devices**, which Server admin doesn't have.
  - Scripts that create or change accounts, roles or API keys with an API key on port 21121 need a signed-in account now.
- On Docker, Connection strategy and the time settings live in the server's database once you save them in the console, and count over `.env` from then on.
- Fields that the server's environment sets can't be changed in the console: the public addresses with `PUBLIC_ENDPOINTS_ENV_OVERRIDE=Y`, the enrollment mode with `ENROLLMENT_MODE_ENV_OVERRIDE=Y`, and the release keys, the client build command and the secrets in `.env`. Change them on the host.
- Settings, Appearance no longer has Enable glass surfaces with tint, Surface blur, Glass opacity and Application description. They changed nothing.
- The device ticket routes are `/api/tickets/nd`.
- Computers that ran the client 1.5.0-rc.4 get a new ID once when they update to 1.5.0-rc.5, and show up as new devices.

## Install

With Docker, the first line installs this release. The second also serves the console over HTTPS at your domain, which has to point at the server, with ports 80 and 443 open:

```bash
curl -fsSL https://raw.githubusercontent.com/neodeskapp/neodesk/main/install.sh | sudo bash -s -- --version 3.6.0-rc.3
curl -fsSL https://raw.githubusercontent.com/neodeskapp/neodesk/main/install.sh | sudo bash -s -- --version 3.6.0-rc.3 --domain <domain> --letsencrypt-email <email-address>
```

The image is `ghcr.io/neodeskapp/neodesk:3.6.0-rc.3`. The [Linux](https://neode.sk/docs/getting-started/linux/) and [Windows](https://neode.sk/docs/getting-started/windows/) pages have the commands without Docker.

## Known issues

- The console's links that open a device in an app use `rustdesk://`. They start stock RustDesk, and on a computer with only the NeoDesk client they open it on Windows and nothing on Linux and macOS.
- HTTPS with Let's Encrypt hasn't been run against Let's Encrypt itself yet, not even its staging server. Whether Traefik replaces a staging certificate when you switch to a real one isn't known, and `--no-traefik` also removes a `TRUST_PROXY` you had set for a proxy of your own.
- Clients that use the console's address as their API server are signed out after the session duration even while they are in use: **Extend session on activity** and **Maximum session lifetime** don't apply to them.
- Some permissions only work together with another one, and the Permissions page doesn't say so. Delete devices, Ban, Change device ID and Change connection mode need Edit devices, and Create and Delete users need Edit users, for example.
- Access rules don't reach devices in device groups that are made from tags.
- Relay servers: the assignment rules are saved but not used; every device uses the default relay.
- USB and drive access and Fleet tasks can't save yet, as the banners on both pages say.
- Each browser session start logs a failed request for the quick support password (409), although the session works.
- A slow single sign-on provider ends in "OIDC authentication failed" or a bare page that says "OIDC callback proxy failed".
